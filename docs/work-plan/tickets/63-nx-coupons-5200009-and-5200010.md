# 63 - The two v84 NX coupons credit nothing when used

**Class:** v84 parity
**Work rows:** R16 - `docs/work-plan/V84-WORK-ROWS.tsv`
**Blocked by:** None - can start immediately

Two whole items v84 added carry a `maplepoint` value and no handler reads it, so using either
consumes the item and credits zero. Neither is obtainable today, so this is a latent gap rather
than a live defect, but the fix is a small read plus an existing credit call. The item-side cash
credit precedent already exists in `Character`.

## R16 - `info/maplepoint` is never read

| item | node | value |
|---|---|---|
| **5200009** | `info/maplepoint` | **1000000** |
| **5200010** | `info/maplepoint` | **10000** |

There are **zero references to either id** anywhere in `src/main/java` or `scripts/`. Both are
v84-new whole items - `add-list/Item.txt:95` and `:96` - so neither has any v83 behaviour to
preserve.

The trap: `getEquipStats` only harvests `inc*`-prefixed nodes. `maplepoint` does not start with
`inc`, so it will never appear in a stat map no matter which stat path is used. It needs a direct
`DataTool.getInt` read off the item's `info` node.

## Precedent

Item-driven cash credit already exists at `Character.java:2084-2088`: `isNxCard` -> 
`getCashShop().gainCash(1, nxGain)`. That is the shape to copy - identify the item, read its value,
call `gainCash`.

The currency argument is the part to get right. `gainCash(1, ...)` is NX; the currency-2 precedent
is `CouponCodeHandler.java:220`, `gainCash(2, quantity)`. `maplepoint` is Maple Points, so the
credit must go to the Maple Point currency and not to NX cash - the node name is the evidence and
`CouponCodeHandler` is the call shape.

## Acceptance criteria

- [ ] Using **5200009** credits **1000000** to the Maple Point currency of the using account, and
      using **5200010** credits **10000**, asserted by a test that stubs the cash shop and reads
      back the credited amount and the currency argument.
- [ ] The amount comes from a `DataTool.getInt` read of `info/maplepoint` on the item, not from a
      literal in Java: changing the WZ leaf changes the credited amount.
- [ ] The item is consumed exactly once per credit - no double-credit on a stacked use.
- [ ] An item with no `info/maplepoint` node routed through the same path credits nothing and does
      not throw.
- [ ] `grep -r 5200009 src/main/java` and `grep -r 5200010 src/main/java` both return at least one
      hit, or the handler is data-driven off `maplepoint` and the test above covers both ids.

Run the new test class with `-Dtest=<Name>`. **Do not run maven while sibling agents are active** -
they collide on `target/`.

## Do not

- Do not route `maplepoint` through `getEquipStats`. It only harvests `inc*`-prefixed nodes and will
  silently return nothing.
- Do not credit NX cash (`gainCash(1, ...)`) for a `maplepoint` node. The node names the currency.
- Do not fold ticket 64 (item 5550001, the timed cash slot expansion) into this one. It shares
  nothing with these two beyond being a cash item and it has no precedent in this repo.
